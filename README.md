# ONCE — Teach once. Let it teach anyone, forever.

ONCE is a **multimodal personal skill-memory application** built for the *Build, Ship, Shape: Amazon Developer Hackathon 2026* (primary track: **Alexa+**, mini challenge: **AWS Builder**).

A person teaches a personal method — by **speaking, typing, or showing a photo**. ONCE turns that teaching into a structured, versioned, persistent **Skill**. Later, the original user or someone they authorize can retrieve it, follow it, and get grounded feedback when reality differs from what was taught. Every skill can be exported as a portable **Agent Skill** folder, and a native macOS helper can answer questions about the window in front of you.

> What makes ONCE different from a chatbot wrapper: **every answer about "what did I teach you" is computed from stored skill records, never generated by a language model.**

## What you can do with it

### 1. Teach a method by text, voice or photo → confirm → save
On `/` you can say *"I pack for a conference with my laptop, charger, badge and water bottle…"* (via browser speech recognition), type it, or upload a photo ("Show me"). The configured AI **proposes a draft** (title, items with aliases, ordered steps, ambiguities). You edit everything, then press **Save as Skill**. Nothing is stored before you confirm — AI never writes to storage directly.

### 2. Ask "what am I missing?" and get a grounded answer
On `/recall` (or via voice and the `/alexa` MCP surface), ask *what am I missing for the conference?*, tick what you already packed, and ONCE — using deterministic retrieval + comparison, **not a language model** — replies with the items it has on record that you have **not confirmed**. The answer always says plainly that *not confirmed ≠ absent*.

### 3. A real browser MCP client (the Alexa+ track path)
Amazon's hackathon FAQ restricts Alexa+ Add-on tools to select partners — participants cannot access them. The allowed alternative is a **self-hosted MCP server (Streamable HTTP, spec `2025-11-25`+) or an Agent Skill, demoed in a web simulator**. `backend/app/mcp_server.py` is a real MCP server with **9 tools**, and `/alexa` is a **real browser MCP client** that performs `initialize` → `notifications/initialized` → `tools/list` → `tools/call`, shows the JSON-RPC traffic, speaks the answers, and hands taught drafts to the review screen. No privileged demo path exists: MCP shares the same stores, authorization rules and recall logic as the HTTP API.

### 4. Native macOS window guide
`macos/OnceWindow` is a menu-bar helper: press **Look at this window**, it captures exactly one visible window, sends it plus your question to `/api/window/guide`, and answers where a control is or how to do something — spoken aloud, with real engine metadata. **Save as skill** turns the answer into a typed `desktop_workflow` skill; **Save SKILL.md** exports it as an Agent Skill folder for your own AI agents. The screenshot is processed in memory and never stored.

### 5. Portable Agent Skills
Any saved skill exports as a `SKILL.md` + JSON manifest (or a zip), from the skill detail page or the MCP tool `once_get_agent_skill`. An AI agent can copy the folder into its skills directory and load the method later.

## Architecture

### High-level shape

```
                         ┌─────────────────────────────┐
     Browser             │  Next.js 16 (App Router)    │
     ────────────────►   │  /  /recall  /skills /alexa │   Next.js rewrites /api/…,
                         │  client pages + MCP client  │   /health, /mcp → same-origin
                         └──────────────┬──────────────┘   (no CORS in dev)
                                        │  fetch (HTTP + JSON-RPC over Streamable HTTP)
                                        ▼
                         ┌─────────────────────────────┐
     Native macOS        │  FastAPI backend (one proc) │  routers: teach, skills,
     ────────────────►   │  HTTP API + MCP @ /mcp      │  recall, window, health
                         └──────────────┬──────────────┘
                                        │  SkillStore interface (server-side authz)
                                        ▼
                          ┌────────────────────────────┐
                          │ mock: InMemorySkillStore   │  tests / offline demos (labeled)
                          │ live: DynamoDB 3 tables    │  ONCE_Skills · ONCE_Sessions · ONCE_Grants
                          │       + private S3 bucket  │  consented evidence
                          └──────────────┬─────────────┘
                                        │
                        ┌───────────────┴─────────────────┐
                        ▼                                 ▼
        Inference (explicit provider)          Reading = deterministic
        proposes *drafts only*                 recall / learning engine
        (openai-compatible / openrouter)       never LLM-generated
```

Key point: **the MCP server enters at the same service layer, not around it.** `/alexa` and the Python smoke client speak the same Streamable HTTP protocol to the same server and tools; neither gets a privileged path.

### Data flow (teach path)

```
Teach (text/voice/photo)
  → POST /api/teach/extract | /extract-image     (AI proposes; draft, not stored)
  → teacher edits & presses "Save as Skill"
  → POST /api/skills  (Pydantic-validated CreateSkillRequest)
  → SkillStore.create_skill  (ownership = owner_id; live: DynamoDB put with idempotency condition)
  → later: GET /api/skills?reader_id=…        (owner OR non-revoked ShareGrant)
           POST /api/recall                  (deterministic match against stored items)
           GET  /api/skills/{id}/agent-skill (read-only SKILL.md projection)
```

The macOS window guide bypasses the draft screen deliberately: `/api/window/guide` answers one question from one capture; only pressing **Save as skill** creates a `desktop_workflow` skill via the same `POST /api/skills`.

## Implementation details

### Backend — FastAPI + Pydantic 2 (`backend/app`)

| Module | Responsibility |
|---|---|
| `routers/teach.py` | `POST /api/teach/extract` (transcript → draft) and `/extract-image` (photo → draft). Full upload validation **before** any provider call: MIME type, magic bytes (JPEG/PNG/WebP), non-empty, ≤ 8 MB — a bad body is a clean 4xx, never a masked 502. In live mode non-configured providers surface an honest 503; mock mode uses a deterministic splitter for text and refuses photo extraction. |
| `routers/skills.py` | Skill CRUD, versioned `PATCH` (bumps `version`, no silent destroy), share/revoke, learner sessions (`start/next/verify`), and `GET /skills/{id}/agent-skill` (`md`/`zip` read-only export). Wrong-reader access returns **404 with no existence leak**. |
| `routers/recall.py` | `POST /api/recall` — grounded "what am I missing" |
| `routers/window_guide.py` | Multipart screenshot + question → vision answer; image handled in memory, never persisted or logged |
| `services/skill_store.py` | The persistence **interface** with server-side ownership checks; mock (in-memory, optionally seeded) and DynamoDB implementations sit behind it. Nobody reaches around it. |
| `services/dynamo_store.py` | Live store: 3 tables + `owner` GSI for list-by-owner; one grant row per `(learnerId, skillId)` so learner listing stays **query-only, no scans**; key remapping (`skillId`/`ownerId`/…). |
| `services/recall.py` | Deterministic retrieval + alias matching + comparison. The model may draft; it may not alter or invent stored items. |
| `services/learning.py` | Mechanic session progression: wrong event, wrong step or wrong DOM element provably does not advance. |
| `services/inference.py` | Explicit primary provider + optional **labeled** fallback (`openai-compatible`, `openrouter`, `gemini`). Every result carries `engine: {provider, model, duration_ms, request_id, fallback_from}`; fallback runs only on provider-level failure and is named in the response. |
| `services/agent_skill.py` | Read-only projection of a readable record into `SKILL.md` + manifest. |
| `services/drafting.py` | Normalizes provider (or deterministic) output into one draft shape for every surface; strips/limits items, aliases and ambiguities. |
| `mcp_server.py` | FastMCP server over **Streamable HTTP** mounted in-process, protected with DNS-rebinding checks. Tools: `once_list_skills`, `once_get_skill`, `once_get_agent_skill`, `once_recall_missing`, `once_start_session`, `once_next_step`, `once_verify_step`, `once_extract_draft`, `once_next_step_model_contract`. |
| `main.py` | Mounts the HTTP routers **and** `mcp.streamable_http_app()` in one process (with the MCP lifespan context), CORS, CORS-free same-origin via Next rewrites. |

### Frontend — Next.js 16 + TypeScript + Tailwind 4 (`frontend/app`)

| Surface | What runs |
|---|---|
| `/` (Teach) | Text, voice (browser `SpeechRecognition`), and photo teaching → editable draft → confirm → save. Drafts taught through `/alexa` are handed off via `sessionStorage` so **Review and save the draft** opens the real draft, not a dead end. Save is validated client-side (empty item/step rows are caught with a named error before hitting the API) and every call carries a hard timeout so the UI can never strand on "Saving…". |
| `/recall` | Grounded missing-item checklist with "have" ticking (per-request, not persisted) and voice entry |
| `/skills`, `/skills/[id]`, `/skills/new` | "My memories & skills", detail/detail-edit, sharing/revocation, agent-skill export buttons |
| `/alexa` | Real browser MCP client (`lib/mcp.ts`): full handshake, tools list, tool call, spoken replies, JSON-RPC traffic drawer, teacher/learner demo profile |
| `next.config.ts` | Same-origin rewrites for `/api/*`, `/health`, `/mcp` → `BACKEND_URL`/`MCP_URL` |

### macOS — SwiftUI (`macos/OnceWindow`)

Menu-bar app that captures the top window on demand (`screencapture`), posts it as multipart PNG to `/api/window/guide` with the voice-typed question, reads `{answer, steps, confidence, engine}`, speaks the answer (`AVSpeechSynthesizer`), and can persist the result as a `desktop_workflow` skill or export `SKILL.md` locally. On-device speech recognition only (microphone never uploaded). Requires Screen Recording permission, granted by the user.

## Data model

The contracts mirror `PRODUCT_SPEC.md` and live in `backend/app/models/core.py` — the single source of truth for both HTTP and DynamoDB serialization.

```
Skill
 ├─ skill_id, owner_id, title, type, version          (skill types: packing | checklist |
 ├─ source: voice | text | photo | camera_demo | …     household_procedure | desktop_workflow |
 ├─ items[]  SkillItem                                 browser_workflow)
 │    ├─ name, required, aliases
 │    ├─ verification: confirmed_packed | visible_packed |      ← the tri-state honesty core:
 │    │                 explicitly_missing | not_verified       "absence of evidence is NOT
 │    └─ evidence_s3_key (private S3 ref, never the bytes)       evidence of absence"
 ├─ steps[]  SkillStep                                        (created_at / updated_at
 │    ├─ order, instruction, screen                          versioned PATCH — no silent edits)
 │    └─ target_element_id, expected_event                   (browser demo steps only)
 ├─ visibility: private | shared
 └─ share_grants[]  ShareGrant { learner_id, granted_by, granted_at, revoked }
```

- **Sessions** (`LearnerSession`) store per-learner step states separately from the taught skill, keyed by `session_id` with a `skill#learner` index for resumption.
- **Grants** are `(learnerId, skillId)` rows in `ONCE_Grants`; learner-side listing queries them instead of scanning skills.

## Non-negotiable invariants

These are enforced in code (see [ARCHITECTURE.md](ARCHITECTURE.md) for the list with exact callouts):

1. Memory is retrieval, not generation — recall reads stored items, the model may not alter or invent them.
2. Not verified ≠ missing — absence of confirmation is reported as *not confirmed*, never *absent*.
3. Ownership and sharing happen server-side; wrong-reader → 404 (no existence leak).
4. Authz never trusts model output; Pydantic validates before persistence.
5. Updates are versioned; nothing is silently replaced.
6. Failure is never masked — live-mode failures are errors; mock is opt-in and labeled everywhere.
7. No credentials in the browser — AWS identity comes from the server-side provider chain; inference keys live only in server env.
8. A screenshot is not a skill — the Mac helper answers from one opted-in window and saves only on your explicit press; the backend does not store the image.
9. Agent Skill export is a read-only projection and uses the same access checks as a read.
10. MCP is not a sidecar demo — same protocol, server and tools for every client.
11. Demo identities (`demo-teacher` / `demo-learner`) are labels, not authentication; production would use Cognito or another IdP.

## Run locally

Prerequisites: **Node 22+**, [uv](https://docs.astral.sh/uv/), and either [Ollama](https://ollama.com) (local models) or an OpenRouter key (hosted inference).

```bash
# 0. optional local models (skip if using OpenRouter)
ollama pull qwen2.5-coder:7b      # text
ollama pull qwen2.5vl:3b          # vision

# 1. backend on :8000 (also serves MCP at /mcp)
cd backend && uv sync
cp .env.example .env              # then set APP_MODE, keys, AWS profile → AWS_SETUP.md
uv run uvicorn app.main:app --port 8000

# 2. frontend on :3000 (proxies /api, /health, /mcp same-origin)
cd frontend && npm install && npm run dev
```

Or run both with one command:

```bash
./scripts/dev.sh                 # live AWS mode
APP_MODE=mock ./scripts/dev.sh   # offline: seeded demo skills, no AWS/Ollama needed
```

Mock mode (`APP_MODE=mock`) exists so judges can run the full teach → recall → `/alexa` loop **without AWS**: a clearly-labeled deterministic parser drafts text teaching (photo teaching honestly refuses, since there is no vision in mock mode), and three demo skills are seeded. `/health` always reports the mode and active inference provider.

## Inference providers

`INFERENCE_PROVIDER` selects the primary; an optional `INFERENCE_FALLBACK_PROVIDER` runs only on provider-level failure and is named in the result (`engine.fallback_from`). It is never a silent substitution and never replaces a real call with mock output.

| Provider | Use | Notes |
|---|---|---|
| `openai-compatible` | Local Ollama or any hosted OpenAI-compatible endpoint | `OPENAI_BASE_URL`, `OPENAI_MODEL`, `OPENAI_VISION_MODEL` |
| `openrouter` | **Active demo path** — hosted models | `google/gemini-3.8-flash` for text and vision (verified with real calls); `OPENROUTER_API_KEY` |
| `gemini` | Google AI Studio via the Interactions API | Model-level fallback only for model/availability errors; account-level `403 PERMISSION_DENIED` is surfaced immediately (documented in FRICTION_LOG.md). Not the active demo path. |

Bounded output (`inference_max_tokens: 2048`) keeps hosted preflight within limits.

## AWS (live mode)

`APP_MODE=live` makes every storage call real: DynamoDB for skills, sessions, grants; private S3 for consented evidence; least-privilege IAM (`once-local` profile for dev, `once-apprunner-backend-instance` role in production). Failures surface as errors, never fakes. Setup is in [AWS_SETUP.md](AWS_SETUP.md); reproducible evidence is in [AWS_EVIDENCE.md](AWS_EVIDENCE.md).

```bash
cd backend && APP_MODE=live AWS_PROFILE=once-local uv run python scripts/smoke_live.py
```

The AWS Builder story is the **verified data and deployment layer** (DynamoDB, S3, App Runner, ECR, Secrets Manager, least-privilege IAM). ONCE never claims AWS AI usage.

## Deployment

The public demo is two AWS App Runner services in `us-east-1`, both built from this repo as `linux/amd64` images stored in ECR:

- **Frontend** (Next.js): `https://nrsvfngagk.us-east-1.awsapprunner.com`
- **Backend + MCP** (FastAPI): `https://m7ypexbma7.us-east-1.awsapprunner.com`

The backend uses the live DynamoDB tables and private S3 bucket through the `once-apprunner-backend-instance` role; the OpenRouter key is injected from Secrets Manager at runtime — nothing is baked into either image. A Render deployment remains as fallback.

Local containers are also supported (Dockerfiles per service + single-host compose with optional Caddy TLS):

```bash
DOMAIN=demo.example.com docker compose --profile https up -d --build
```

Full env-var matrix, per-service commands, and the public-demo access warning: [DEPLOYMENT.md](DEPLOYMENT.md).

## Status and honest limits

**Working and verified:** multimodal teach → draft → confirm → persist (all sources), real labeled AI extraction (OpenRouter text + vision; local Ollama fallback), grounded recall with **not-confirmed** semantics, skill CRUD + versioned edits + sharing, MCP server (protocol `2025-11-25`) + real browser client + 9-check independent smoke, portable Agent Skill export, native macOS window guide with real vision calls and save-as-skill, live AWS data layer with scoped IAM and 4/4 live smoke, public App Runner demo, production hardening of the save path (client-side draft validation, request timeouts, readable validation errors, image magic-byte checks). Remaining before submission: record the < 3-min demo video and submit the Devpost entry.

**Stated limits (not hidden):**

- `demo-teacher` / `demo-learner` are demo identity labels, **not authentication**; server-side ownership/share checks are real for the selected id. Production would use Cognito or another IdP.
- The backend learning engine is not exposed by the shipped browser UI (product direction); the Mac window guide is a separate opt-in desktop surface, not a browser automation feature.
- Alexa+ Add-on SDK access is select-partner only and is **not claimed**; the MCP server + web simulator is the allowed path, and the UI says so.
- The macOS helper needs Screen Recording permission and a live vision model; it never captures in the background and never stores screenshots.
- Agent Skill export is a portable folder — it does not install itself into an agent's directory.
- Window guidance answers from one screenshot plus stable macOS conventions; it does not click controls or know what is off-screen.
